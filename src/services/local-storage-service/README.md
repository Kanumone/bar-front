# Новая архитектура сохранения данных

## Обзор изменений

Система сохранения данных была переработана для повышения производительности и надежности:

### ✅ Что изменилось:

1. **localStorage как основное хранилище** - все изменения состояния игрока сохраняются локально
2. **Пакетная синхронизация** - данные отправляются на backend раз в минуту
3. **Улучшенное логирование** - логи отправляются сразу на backend с резервным сохранением
4. **Автономная работа** - игра работает без интернета, синхронизируется при восстановлении связи

### ❌ Что НЕ изменилось:

- Логирование продолжает работать как раньше (сразу на backend)
- API интеграция остается той же
- Интерфейсы компонентов не изменились

## Архитектура

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│   User Action   │───▶│   localStorage   │───▶│    Backend      │
│   (immediate)   │    │   (immediate)    │    │  (every 1 min)  │
└─────────────────┘    └─────────────────┘    └─────────────────┘

┌─────────────────┐                           ┌─────────────────┐
│     Logging     │──────────────────────────▶│    Backend      │
│   (immediate)   │                           │   (immediate)   │
└─────────────────┘                           └─────────────────┘
```

## Сервисы

### LocalStorageService

Управляет сохранением и загрузкой данных в localStorage:

```typescript
// Сохранение состояния игрока
LocalStorageService.savePlayerState(playerState);

// Загрузка состояния игрока
const state = LocalStorageService.getPlayerState();

// Проверка необходимости синхронизации
const needsSync = LocalStorageService.needsSynchronization();

// Очистка всех данных
LocalStorageService.clearGameData();
```

### SyncService

Автоматическая синхронизация с backend:

```typescript
// Запуск автосинхронизации (каждую минуту)
syncService.start();

// Принудительная синхронизация
await syncService.forcSync();

// Остановка синхронизации
syncService.stop();

// Получение статуса
const status = syncService.getStatus();
```

### LoggingService

Логирование с резервным сохранением:

```typescript
// Отправка лога (с резервным сохранением при ошибке)
await LoggingService.logActivity('action', details, 'scene');

// Отправка накопленных логов
LoggingService.sendPendingLogs();

// Статус накопленных логов
const status = LoggingService.getPendingLogsStatus();
```

## Использование в компонентах

### PlayerStore

Все методы player store теперь сохраняют в localStorage:

```typescript
const playerStore = usePlayerState();

// Эти методы автоматически сохраняют в localStorage
playerStore.setEnergy(15);
playerStore.addMoney(100);
playerStore.setProgress('newScene');

// Управление синхронизацией
playerStore.startAutoSync();     // Запуск автосинхронизации
playerStore.stopAutoSync();      // Остановка
await playerStore.forceSync();   // Принудительная синхронизация

// Работа с localStorage
playerStore.loadPlayerStateFromLocal();      // Загрузка из localStorage
playerStore.loadPlayerStateFromServer();     // Загрузка с сервера
```

### AuthStore

При входе в систему:

1. Загружается состояние из localStorage
2. Загружается состояние с сервера
3. Запускается автосинхронизация
4. Отправляются накопленные логи

При выходе:

1. Останавливается автосинхронизация
2. Очищаются токены (localStorage данные игры остаются)

## Отладка

### Debug Panel

Для разработчиков доступна дебаг панель:

- **Активация**: `Ctrl+Shift+D` или установить `localStorage.setItem('debug-mode', 'true')`
- **Функции**:
  - Просмотр текущего состояния игрока
  - Статус синхронизации
  - Количество накопленных логов
  - Тестирование функций
  - Принудительная синхронизация
  - Очистка локальных данных

### Логирование в консоли

Все операции логируются в консоль с префиксами:

- `[SyncService]` - автосинхронизация
- `[Logging]` - система логирования
- `[Activity Logged]` - успешные логи

## Обработка ошибок

### Сетевые ошибки

- При потере соединения данные накапливаются в localStorage
- При восстановлении связи происходит автоматическая синхронизация
- Логи сохраняются локально и отправляются при возможности

### Ошибки localStorage

- Все ошибки логируются через `logAppError`
- При критических ошибках игра продолжает работать без сохранения

### Повторные попытки

- SyncService делает до 3 попыток при ошибке
- Интервал между попытками: 5 секунд
- После превышения лимита ждет до следующего цикла (1 минута)

## Производительность

### Оптимизации

- localStorage операции минимизированы
- Синхронизация происходит только при наличии изменений
- Логи отправляются пакетами
- Автоматическое ограничение количества накопленных логов (100 штук)

### Мониторинг

- Время последнего сохранения
- Количество попыток синхронизации
- Статус подключения
- Размер накопленных данных

## Migration Guide

### Для разработчиков

Никаких изменений в коде компонентов не требуется! Все изменения инкапсулированы в сервисах.

### Для тестирования

1. Включите дебаг панель: `Ctrl+Shift+D`
2. Тестируйте различные сценарии:
   - Работа без интернета
   - Восстановление соединения
   - Выход/вход в систему
3. Мониторьте логи в консоли
4. Проверяйте данные в localStorage (DevTools → Application → Local Storage)

## Ключи localStorage

- `bar-game-player-state` - состояние игрока
- `bar-game-progress` - прогресс игры
- `bar-game-pending-logs` - накопленные логи
- `debug-mode` - режим отладки
